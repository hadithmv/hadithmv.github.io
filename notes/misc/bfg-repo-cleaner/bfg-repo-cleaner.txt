The mismatch makes sense now — `git reset --hard origin/main` only moves your `main` branch pointer; it doesn't touch your **local tags**. You still have 44 local tags (`2.0`, `2.01`, ... `6.9.39`) pointing at the **old**, pre-rewrite commit hashes. Since those tags are still reachable refs in your local repo, `git gc --prune=now` can't touch the old objects they point to — they're "still in use" as far as git is concerned, so the old ~6 GB of history stays alive locally even though GitHub's copy is clean.

## Fix: delete and re-fetch tags to match the rewritten remote

```powershell
cd D:\hadithmv\hadithmv.github.io

# delete all local tags
git tag | ForEach-Object { git tag -d $_ }

# fetch fresh tags from the rewritten remote
git fetch origin --tags --prune

# now gc again
git reflog expire --expire=now --all && git gc --prune=now --aggressive

du -sh .
```

That should drop you down close to the 1.7 GB your mirror clone showed (or lower, since your mirror clone was made before the folder-removal-from-HEAD commit — your local should now reflect that removal too).

```
Look for anything under `refs/remotes/`, `refs/stash`, or leftover branches pointing at old hashes — those would need the same treatment (delete locally, refetch).

## Problem 1: BFG protected your current HEAD commit
Look at this part of your first run's output:

```
Protected commits
-----------------
 * commit fe860772 (protected by 'HEAD') - contains 51 dirty files :
        - app/androidApp-kt/app/src/main/assets/js/json/HDT-all.json (2.9 MB)
        - app/androidApp-kt/app/src/main/assets/js/json/HDT-muwattaMalik.json (4.6 MB)

BFG **refuses to strip content that exists in your current HEAD commit** by default — it only cleans up *old* history, not your live tip. Since `app/`, `androidApp-kt/`, etc. are still sitting in your actual latest commit on GitHub right now (you only excluded them at the *mirror* stage with `rm -rf` in the GitHub Action — that never removed them from the real repo), BFG can shrink old history around them, but the files themselves are still live at HEAD and keep taking space.

**Fix:** you need to actually remove these folders from your real repo with a normal commit, *then* run BFG to clean the old history left behind.
